# Another RAG 界面设计准备

2026-11-06 更新：本文作为未托管界面的设计参考，不表示前端已经部署。本次不检查云端目标文件、团队或授权状态，不将本地目录或 Git 提交冒充 Figma 文件。运行能力以[项目 README](../README.md)为准。

## 设计目标

为中英双语 Q&A TXT 的导入、检索与最终 LLM 输入检查提供工作型界面。
采用克制、紧凑的信息布局；首屏进入实际工作区，不增加营销落地页或大型 Hero。
Figma 是开发工具，运行中的后端服务不依赖用户登录 Figma。

## 页面范围

| 页面 | 主要内容 | 现有后端接口 |
|---|---|---|
| TXT 导入 | 文件选择、标题、上传状态、文档及节点数量、错误提示 | `POST /v1/qa/ingest` |
| 检索与问答 | Query、答案或“无”、参考上下文、加载及失败状态 | `POST /v1/chat/query` |
| 检索诊断 | Vector、BM25、RRF、Rerank 候选、排名与分数 | `POST /debug/v1/retrieval/trace` |
| LLM 输入预览 | 最终 model、messages、Prompt 和上下文；不触发生成 | `POST /debug/v1/generation/input` |
| 服务状态 | 应用健康、数据库就绪及异常状态 | `GET /health`、`GET /ready` |
| 文档管理 | 绑定库内的列表、搜索、分页、预览与按版本删除 | `GET /v1/documents`、`GET /v1/documents/{id}/preview`、`DELETE /v1/documents/{id}` |
| 多轮会话 | 创建/列出会话、提交追问、读取展示记录 | `/v1/conversations`、`/v1/conversations/{id}/turns` |

文档列表、预览、删除和多轮会话已有业务接口；知识库创建/删除/切换仍通过 CLI，API 进程固定绑定单库。批量任务和完整公网用户权限管理没有因此实现，不能在设计中模拟成功。
Debug 页面只在后端启用诊断接口时可用；输入预览要求 `QUERY_FUSION_NUM_QUERIES=1`。
当前保留静态 HTML/JavaScript 参考稿，API 不挂载首页、静态目录或网页专用上下文端口；后续页面开发需另定范围，不因文档更新引入新的运行依赖。

## 设计检查

- 提供桌面和移动布局，至少覆盖 1440、768 和 390 像素宽度。
- 中文、英文和长文件名能够换行，不遮挡相邻内容；表格允许受控横向滚动。
- 工具按钮采用可识别图标并带 Tooltip，模式用分段控制，数值用输入框或步进器。
- 覆盖空数据、加载、成功、无答案、数据库故障和请求失败状态。
- 使用 Auto Layout、组件和变量组织可编辑画布，而非仅上传一张截图。
- 界面状态和字段以 `docs/interfaces.md` 为准，不为了设计擅自更改后端契约。

## 数据与写入边界

设计样例使用虚构的通用 Q&A，不把实际入库 TXT、完整检索日志或 Prompt 上传 Figma。
没有用户明确授权时，不修改现有团队文件，不消耗额外付费生成额度。
首次写入前确认文件归属和操作范围；已有文件修改优先新增页面或独立 Frame，避免覆盖已有设计。
