# 历史原文读取补丁与验收

> 2026-11-06 文档核对：本文保留 2026-10-31 的实现及验收范围；当前部署和导航见[项目 README](../README.md)与[文档导航](README.md)。本次未重新运行真实模型验收。

## 范围与基线

修复检索前历史定位和生成前上下文组装之间的断点。补丁前基线为
`5131552` / `V1.3-rebuild.1`。历史用户原话和成功返回的回答继续保存在 PostgreSQL
`conversation_display_turns`；Qdrant、TXT、Embedding、Reranker 和计算题仅检索规则不变。

本补丁不迁移正式数据库。分题答案的字符区间、哈希和来源引用使用现有题目版本
`effective_state` JSONB 保存，整轮答案仍保存在既有展示表，不复制到向量索引。

## 实际处理路径

1. 现有 LlamaIndex `structured_predict` 规划输出可选的 `history_content`。
2. 程序核验 session、数据库 UUID、存储指纹、请求开始 revision 和请求时间边界。
3. `HistoryContentPipeline.read` 定向读取原文，区分第一轮、上一轮、指定轮次和稳定题号。
4. `read_user` / `read_answer` 直接返回保存内容，不经过知识检索、答案生成或知识门控。
5. `transform` 使用旧答案作为素材，执行生成和忠实于原文的逐题门控。
6. `followup` 读取原题与必要回答帮助理解，按当前条件检索；旧回答不变成知识证据。
7. 合并返回并短事务保存本轮可见结果。复述/转换作为独立题目记录，不覆盖原题状态。

自然语言 `ask` 仍可能调用一次规划模型；直接回读不是宣称整条命令零 LLM 调用。
CLI 仍按已有方式初始化所选库与模型配置，没有增加脱离知识库运行的历史浏览器。

## 使用示例

保持既有 CLI 启动方式，在选择知识库与对话后使用：

```text
ask "我第一个问题是什么？"
ask "第一个问题你回答了什么？"
ask "把第一轮的原回答原样发我。"
ask "把刚才的回答改成表格。"
ask "接着第一轮的问题详细解释一下。"
ask "把第一轮原回答原样发我，同时补充解释 RAG 的作用。"
```

第一轮与第一题并非同一概念。成功轮次用 `turn_sequence`，稳定题号用 `question_no`，
某轮内部第几题用 `question_order`。第一条输入可能是失败请求，此时可以读用户原话，
但没有成功答案可供复述。自然语言歧义由规划/定位环节明确澄清。

## 生产与诊断接口

既有 `POST /v1/conversations/{session_id}/turns` 和 CLI `ask` 入参不变。
`items` 兼容新增：

| 字段              | 含义                                                |
| --------------- | ------------------------------------------------- |
| `response_kind` | `knowledge`、`history_quote` 或 `history_transform` |
| `history_refs`  | 来源轮次、可用时的题目版本、用户/助手角色和内容哈希                        |
| `error_code`    | 精确历史读取/校验错误，不用知识库“无”掩盖读取故障                        |

单项原样读取时 `answer` 与保存正文一致，保留首尾空白和换行；多项合并时外层有编号，
每项 `items[].answer` 保留原文。引用通过 `history_refs` 返回，不插入原文正文。

存储端口为 `PostgresSessionStore.read_history_content(session_id, binding,
as_of_revision, before_turn_id, query)`。读取必须限定到当前已认领请求之前，不能跨会话、
跨库或读取请求开始时尚不存在的成功版本，不将原回答替换成该题当前最新版。

规划查询结构：

```json
{
  "operation": "read_answer",
  "selection": "turn",
  "turn_sequence": 1,
  "question_no": null,
  "question_order": null,
  "question_version": null,
  "version_selection": "first"
}
```

- `selection` 为 `first_turn/previous_turn/turn/question`。
- `turn` 必须有 `turn_sequence`；`question` 必须有稳定 `question_no`。
- `question_version` 只用于 `question`；省略时通过 `first/latest` 选择。
- `question_order` 按该轮当时的结果顺序排列，不按全局题号重新排序。
- 请求级 `reply_to_question_id` 仅作为未明确指定其他位置时的默认目标。
- `use_history=false` 与读取冲突时返回 `HISTORY_DISABLED`，不会暗中读取。

诊断沿用 `ConversationWorkflow.answer_turn(..., plan=..., diagnostic=True)` 和
`preview_turn`：可注入经校验的计划、Mock 模型和隔离存储，检查实际最终 messages。
完整正文只在显式诊断输入输出中展示；生产 trace/日志默认记录操作、状态、来源引用、
逐题错误码、预算和耗时。常规失败也保留安全的逐题失败摘要，便于定位门控问题。

## 保真、状态与容量边界

- 旧回答只证明系统当时说过什么，不证明其中事实现在正确。
- 知识源删除不自动删除聊天原文；补充事实仍需当前有效知识证据。
- 未保存正文返回 `HISTORY_NOT_RETAINED`；无目标返回 `HISTORY_NOT_FOUND`；
  多题指代不唯一返回 `HISTORY_AMBIGUOUS`；读取故障返回 `HISTORY_READ_FAILED`。
- 失败/unknown 请求的内部候选不得作为历史答案返回，unknown 恢复保护继续生效。
- 旧多题记录无可靠映射时返回 `HISTORY_ITEM_MAPPING_MISSING`，提示读取整轮；
  不按标题或数字猜切。新回答按实际合并位置保存字符区间与 SHA-256。
- 原样读取不截断正文，超出护栏明确要求缩小范围。长文转换先检查完整改写预算并留余量，
  容量不足返回 `HISTORY_TRANSFORM_TOO_LONG`，不静默压缩或漏项。
- 历史指令作为引用文本处理。改写模型与门控将它标为不可信素材；该约束仍需真实模型
  专项验证，不能用 Mock 测试宣称解决所有提示注入。

## 验收方法

新增 `tests/test_history_content.py`，专项共 48 项。六种主场景分别覆盖近期、超出目录、重启后读取；
另覆盖版本/范围隔离、无正文、失败记录、无知识证据、长正文、混合问题、分题映射、重放、
原题状态保护和 LlamaIndex 原生规划到 Workflow 的连接。

使用隔离 PostgreSQL 与 Mock 规划/生成/门控，不以正式会话作夹具，不调用付费 API。
Mock 通过说明路由、存储和校验契约可运行，不等于真实模型理解及改写质量已验收。
输出使用新的 `reports/hr_*` 目录和 XML，既有报告不覆盖。

本轮验收结果：历史读取专项 48 passed，另有多题追问边界 1 passed，分别记录于
`reports/hr_final_20261031_7c62.xml` 和 `reports/hr_multi_followup_20261031_90cb.xml`。
会话工作流/生成/规划/定位/账本/展示/CLI/API/修复/证据映射/历史读取综合回归 159 passed，
报告为 `reports/history_patch_final_20261031_c56e.xml`。Ruff、代码映射刷新和差异空白检查通过。
未调用真实 DeepSeek；真实模型对中文口语历史目标识别和长答案转换质量仍未验收。
