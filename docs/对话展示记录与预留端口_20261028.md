# 对话展示记录与后端端口

> 更新核对：2026-11-06。文件名保留原实施日期；端口已经实现。2026-10-31 历史正文回读扩展已纳入下述当前说明。

## 范围

当前不托管自定义前端。后端在 PostgreSQL 独立展示表记录每轮用户原话和最终可见回答，不为聊天正文新建向量索引。
题目与对象账本继续作为身份和条件版本依据；专门的历史正文读取端口可在会话、库绑定、revision 和请求时间边界核验后回读原话/原答，用于历史定位、原样复述、格式转换或追问。
完整正文不会默认全量回灌，历史助手答案也不被当作知识库事实证据。当前实现见[历史原文读取](历史原文读取补丁与验收_20261031.md)。

## 数据契约

展示表为 conversation_display_turns，以 (session_id, turn_id) 关联 turn_requests，每个请求至多一行：

| 字段 | 含义 |
| --- | --- |
| session_id, turn_id | 稳定轮次身份；联合主键和外键 |
| user_message | 该请求的原始用户文本 |
| assistant_answer | 最终实际返回的文本；整轮失败或结果未知时为 NULL |
| created_at | 稳定分页排序的创建时间 |

状态、request_id、已提交序号、失败码和用量继续从 turn_requests 读取，避免重复存储。最终可见文本包括合并多题后的答案、澄清、部分回答、无依据项及普通交互回复；不保存模型中间稿、完整 Prompt、原始响应、检索节点正文或失败候选答案。

用户原话与请求认领同事务写入；最终回答只在逐题校验完成后，与结构化轮次、revision 和索引 outbox 同事务写入。确定失败保留原话与失败状态，回答为 NULL；unknown 不能被伪装成成功或自动重发。同一 request_id 重放不追加展示行。旧账本只有请求摘要及答案哈希，不能自动补回旧正文。

## 生产端口

- GET /v1/conversations/{session_id}/turns?limit=50&cursor=...：在现有知识库绑定和会话范围内，按 (created_at, turn_id) 稳定分页读取展示记录；limit 默认为 50，范围为 1–100，cursor 是上一页返回的 next_cursor（轮次 UUID）。响应包含 items 与 next_cursor；每项包含 user_message、可空 assistant_answer、status、request_id、turn_sequence、failure_code、answer_not_retained、created_at。失败码可供客户端生成用户可见提示；空回答不等于“无”。
- 现有 POST /v1/conversations/{session_id}/turns 保持提问入口；同 ID 成功重放可读取展示记录返回最终答案，旧记录缺正文时维持 answer_not_retained=true。
- CLI 与 HTTP 使用同一会话存储；CLI 的 ask 成功重放也从展示表读取最终回答。未来前端只能通过生产读取接口显示记录，不直接连 PostgreSQL。诊断端口 inspect_display_scope 仅返回展示轮次数与已存回答数，不导出正文或模型中间态。

源码端口与 PostgreSQL 第 5 版迁移已实现。应用不会自动迁移数据库；核对 STORY_RAG_POSTGRES_DSN 与 STORY_RAG_POSTGRES_SCHEMA 后，显式执行 uv run python scripts/migrate_conversations.py --apply。未达到要求版本的实例不能继续使用会话能力。原实施验证使用隔离数据库；本次文档更新未迁移任何实例。

## 验收与边界

覆盖成功、部分成功、交互回复、整轮失败、unknown、幂等重放、进程重启、分页、跨会话/跨库拒绝、旧行缺正文和 use_history=false。正式部署面对多用户时，必须额外实现用户级会话授权；会话 UUID 与知识库绑定本身不等于用户鉴权。归档只隐藏会话；展示记录的最终删除与保留期限另行确定。
