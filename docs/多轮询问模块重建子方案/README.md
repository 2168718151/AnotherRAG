## 拆分原则

把原方案拆成 6 个可顺序验收的子方案。每个子方案完成后，都使用同一份五轮连续对话做快速回归；不为不同模块另造用户问题、替换措辞或增加第二组对话。唯一用例原文见[00-唯一连续回归用例.md](00-唯一连续回归用例.md)。

单个子方案的快速测试可以只执行该阶段负责的检查，但输入仍来自这份固定对话。上游模块以冻结的阶段结果或 Mock 注入，下游模块用断言替代；集成验收再用同一会话从第一轮跑到第五轮。这样可以快速定位阶段回归，也避免把“Mock 通过”误报成模型理解或答案质量已通过。

原设计方案中的 72 个定向场景和 12 组真实会话仍是原始完整测试设计。本次拆分遵守“每个子方案只用一个对话用例”的约束，不把它们扩写成新的用户对话。单一案例无法穷尽跨会话攻击、并发、各类截断和全部输入边界；这些风险需通过同一用例的参数化程序断言、故障注入和隔离数据夹具覆盖，不能声称一个自然语言案例本身覆盖所有极端情况。

## 公共验收规则

- 测试会话使用隔离 PostgreSQL schema 或专用测试数据库，并绑定固定知识库 UUID 与存储指纹；不得触碰主库数据。
- 测试以同一固定对话的五轮原文作为唯一用户输入。测试夹具可准备权威知识片段、任务状态和调用记录，不得把夹具改写成另一段对话。
- 每轮同时检查最终回答与内部结构：目标映射、历史引用、条件来源、证据范围、阶段状态和最终 revision。
- 未提供调用记录前，第一轮的独立工单失败原因必须保持未确定。第五轮新增记录后，判断必须收敛到 `missing_write_scope` 的授权策略拒绝，且执行器未调用业务接口、未创建工单。
- 用户确认只表达对明确变更内容的同意，不替代服务端授权；确认结果不得跨目标、跨参数、跨资源或跨时效复用。
- 第四轮的人工审批平台限制只修订草稿修改流程，不改写通用 Agent 写权限原则；聊天中的“同意”不能绕过平台。
- Mock 回归只证明程序对冻结输入的处理符合契约。模型是否能稳定理解和回答，必须另以同一用例的真实模型结果按人工冻结的评分表评估。
- 生产应用日志与 LlamaIndex 日志写入项目 `logs/`；测试报告、完整 prompt 和原文的保留范围按原设计方案执行。
