# 子方案 5：预算内生成、逐题校验与合并回答

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

依据：[总览](README.md)、[原重建设计方案第 7 至 9、13 节及第 17.5 节](多轮询问模块重建设计方案_20261021.md)。

## 目标

将有效历史、当前任务和各题许可证据组装成受预算约束的 LLM 输入，产出结构化逐题回答；使用程序断言和逐题语义门控后按原始目标顺序合并。失败题不得抹掉其他已通过题目。

## 范围

- 预算先覆盖规划/历史摘要、用户本轮目标、证据、输出 schema、生成与门控输入，并留安全余量。
- 规划和门控使用显式模型参数；最终 HTTP 请求体必须通过适配器契约测试核对。
- 每次流式调用使用隔离缓冲，拒绝将 reasoning 当答案正文；空正文、截断或非法结构不得下传。
- 先执行题号、版本、目标覆盖、允许证据、来源版本、禁止条件、语言/格式及必要确定性检查。
- 再按题执行相关性、事实支持与忠实度审核；有限局部修复后重跑全套检查。
- 根据每题状态输出已回答内容、部分结果、聚焦澄清或“无”；技术失败单独报告。
- 依照第四轮业务限制，说明助手提交变更单、人工审批平台负责审批/执行，最终以平台结果确认成功。
- 第五轮分别回答已验证失败原因和是否应授予写权限；后者需业务/安全责任方决定，诊断结论不能自动触发授权变更。

## 不在本阶段

不增加本地生成小模型、不把整段历史或完整答案写入长期账本、不固定逐题调用再总结，也不把模型的“Yes/No”作为唯一门控。失败后如何原子提交或恢复由子方案 6 验收。

## 唯一快速测试

使用[唯一连续回归用例](00-唯一连续回归用例.md)五轮原文。用固定证据、冻结任务计划和 Mock LLM/门控结果测试消息组装、响应解析和逐题校验；该快速测试不调用 DeepSeek，不增加其他对话。

阶段断言：

- 五轮所有明确问题和限制均覆盖；特别检查第一轮不猜工单根因、第四轮不改通用原则、第五轮不把缺少 scope 的事实偷换成“应该授予”。
- 第五轮答复精确区分已通过（Schema、身份认证、租户/资源归属）、拒绝点（权限策略缺少写 scope）和未执行（业务接口、记录创建）；不得称为超时或响应丢失。
- 草稿写操作不得由助手直接调用业务写接口；平台申请成功与业务修改成功是不同状态，只有平台最终执行回执才能确认执行。
- 用户确认与服务端授权分别校验；目标/参数/版本/授权变化时确认失效；任一题引用越权、漏项、空正文或截断都不能标记 answered。
- 最终合并保留各任务状态与出处，回答顺序清晰，不将工单环境的权限结论套用于草稿工作流。

## 完成标准

固定输入输出契约、响应结构、逐题门控和合并断言全部通过。Mock 结果仅代表组装与验证逻辑正确；回答质量需用同一固定对话的真实模型输出另行评分，不能由格式测试代替。

## 实现与预算口径（2026-10-25）

- `src/story_rag/pipelines/conversation_generation.py` 使用 LlamaIndex 原生 `PromptTemplate` 与 `PydanticOutputParser`，每个可答任务生成一个带题目 ID/版本的 item；程序检查重复/漏项、引文范围、显式算式和禁止动作，再按题调用结构化语义门控。可答项与待补、无依据、技术失败项分别合并，不用整轮 Yes/No 清空已通过结果。
- `src/story_rag/pipelines/token_budget.py` 的应用护栏为 65,536 上下文、4,096 安全余量；规划、生成、门控输出预留分别为 8,192、20,480、4,096。单题答案上限 4,096 UTF-8 字节；每批最多两题。生成预留按 JSON 转义后的最坏常见正文计算，门控预检同样为最坏候选答案和全部许可引用预留；异常控制字符拒绝。容量不足则拆批，单题仍超限时在调用前明确失败，不静默裁剪目标。
- 定向验收比运行时最低阈值更严格：每批生成输出余量至少 1,536、门控输出余量至少 2,048，两个阶段的上下文余量各至少 4,096；真实 usage 已知时还检查发送输入不超过保守估算、实际输出距上限至少 1,024。预留不等于实耗；未知 usage 不记零。
- 历史修订按时间保留在有效题目中，后来的明确修改覆盖冲突条件，仍适用的早期限制成为逐题要求。过长历史显式报错，不截掉条件。禁止通知/发布/删除草稿的显式动作有窄范围程序检查；其他改写及事实支持仍需语义门控，不能把关键词检查等同于通用安全证明。
- 真实五轮报告使用固定 Mock 证据和隔离 PostgreSQL；它验证真实规划、生成、门控与账本连接，不验证真实 Qdrant 的检索质量。完整 Prompt 仅写到被 Git 忽略的诊断报告，生产账本不存答案正文。
- 生效要求把规划输出中的限制与禁止动作持久保留；明确“同样适用于另一任务”的共同变化只传递该来源任务的约束。解析后已补齐的缺口不继续继承旧的“信息未提供”要求。生成前把历史禁止动作送入本题校验，不允许在后续轮次重新建议通知。
- 对显式命名的多租户、队列和共享服务账号要求执行双语术语下限校验；仅写“执行身份”不能算覆盖“共享服务账号”。该校验不替代语义忠实度判断。禁止动作程序检查容许“禁止、拒绝通知”的否定描述，同时阻断实际通知建议。
- 门控输入列出合法的逐题要求索引；索引分区错误或对“实现细节未提供”的不确定性提示误判时，最多进行一次门控重审，不重生成答案。单题仍须经过证据与范围审核；不把一题的输出失败扩散为其他题的无依据。
- 方案 0 的真实五轮验收：题数 3、2、2、1、2，首轮两题 answered、一题 waiting_input，其余全部 answered；保守预算与真实输出余量详见[验收记录](方案五六验收记录_20261025.md)。
