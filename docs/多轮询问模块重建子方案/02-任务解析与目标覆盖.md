# 子方案 2：任务解析、分题与目标覆盖

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

依据：[总览](README.md)、[原重建设计方案第 3、4、8、9 节](../多轮询问模块重建设计方案_20261021.md)。

## 目标

将每轮消息解析成完整、可追踪的任务计划，保留原始目标与输出要求，区分独立问题、同一问题的多个要求、补充、更正、比较、真实依赖和不确定关系。模型只提供候选解析；题号、历史身份、范围和持久化状态由程序校验。

## 范围

- 使用现有 DeepSeek API 和 LlamaIndex 结构化输出能力解析整条消息，不按每个子问题重复调用规划。
- 规划 Schema、版本、字段校验、原文目标映射和有限 JSON 修复。
- 多任务覆盖检查：每个原始意图必须映射到一个或多个计划任务；模糊关系不强行合并。
- 识别任务所属对象、目标、约束、禁止动作、所需历史、输出形式和依赖候选。
- 明确区分“当前消息中没有给出事实”和“模型猜测补齐”。

## 不在本阶段

不决定某个历史题目的真实身份、不应用历史条件、不做知识检索、不执行计算、不生成最终答案。固定 prompt 与 HTTP 最终发送参数的严格契约在子方案 5/6 验收。

## 唯一快速测试

使用[唯一连续回归用例](00-唯一连续回归用例.md)的五轮原文，通过固定模型响应/Mock 规划器运行；不新增改写题或独立对话。

阶段断言：

- 第 1 轮至少分出通用权限原则、单租户草稿流程和“证据不足、待补调用记录”的工单诊断目标；禁止操作作为显式约束保留。
- 第 2 轮识别多租户、异步队列、共享服务账号，并标出需同步更新的通用原则与草稿流程。
- 第 3 轮保留确认范围、请求/目标变化、撤权、资源变化、提交前复核和失效处理等要求，不合并成笼统的“用户确认”。
- 第 4 轮标注范围限定为草稿业务流程变更，并显式保留通用权限原则不变。
- 第 5 轮识别为独立工单环境的诊断任务；已给定记录是证据，不将其转换为授予权限的命令。
- 五轮每项用户目标均有映射；不能因为相似主题而合并不同环境或删除限制。

## 完成标准

冻结的结构化计划通过 Schema、目标覆盖、约束保留和任务关系断言；非法 JSON、未知字段、缺失目标不得继续进入检索或生成。真实模型是否稳定产生同样解析结果不由 Mock 通过替代。

## 实现记录

- 生产实现位于 `src/story_rag/pipelines/task_planning.py`，使用 LlamaIndex `LLM.structured_predict()` 和版本化 Pydantic 结构；信息缺口显式区分 `explicitly_missing`、`not_provided`、`uncertain`。
- `TaskPlanningProductionPort.plan()` 对整条消息规划；有效输出一次调用，结构/来源校验失败最多一次修复。模型异常不按格式错误重试。
- `TaskPlanningDebugPort.validate_candidate()` 注入固定计划，不调用模型。目标/任务键只在当前计划内有效；未连接历史身份、检索、生成或 PostgreSQL 持久化。
- 五轮唯一用例由 `tests/test_task_planning.py` 读取并通过固定计划验证：定向测试 15 passed；完整 Ruff 通过；全量测试 244 passed、2 skipped。两项跳过均因 LM Studio Embedding 端点不可达。
- 本轮未调用 DeepSeek，Mock/冻结计划不构成真实模型理解质量验收。完整边界与版本状态记录在项目 `MEMORY.md`。
