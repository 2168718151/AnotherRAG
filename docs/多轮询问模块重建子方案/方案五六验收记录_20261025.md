## 预算核对

应用护栏为 65,536 上下文、4,096 安全余量；单题最多 4,096 UTF-8 字节、每生成批最多两题；生成输出预留 20,480，门控输出预留 4,096。预检包含消息和格式开销、JSON 转义、最坏候选答案、完整证据 ID 与一次门控格式重审。

| 全五轮最小余量 | Tokens |
| --- | ---: |
| 规划上下文 | 40,305 |
| 生成上下文 | 29,971 |
| 门控上下文（含重审预留） | 24,629 |
| 生成输出（按两题最坏转义预留后） | 3,673 |
| 门控输出 | 2,048 |
| 真实返回与对应输出上限 | 3,833 |

本次共 15 次 API 调用：五次规划、五次生成、五次门控。生成/门控 10 次调用均取得 provider usage，合计 27,608 tokens；规划的五次 usage 在当前适配层不可用，不能记为零或将 27,608 误报为总计费量。账本的 132,103 `accounted_tokens` 含未知 usage 的保守预留，也不是 provider 账单数字。全部已知生成/门控实际输入均低于保守输入估算，返回均以 `stop` 结束，没有 `length` 截断。

## 对照原方案与旧 Bug

- B12：先保留原目标，再检查输出题数；跨题“同步修订”要求由整轮两题覆盖，不能让其中一题重复回答另一题，也不能新增仅用于“保持不变”的伪答案。
- B13：历史修订继承已生效约束和禁止动作，覆盖冲突的初始单租户/同步条件；第五轮工单补充后不继承第一轮“日志未提供”的旧缺口。
- B18/B19：规划、生成和门控使用阶段参数与保守预检；实际 HTTP 参数另由隔离 HTTP 契约测试核对，不能只看 Python 调用参数。
- B23：逐题结构化门控、合法索引分区及一次有界门控重审。禁止动作的否定说明不误拒；无法确定的实现细节提示不自动变成幻觉结论。旧 MT15、MT31、MT36/U1 原语料误拒场景尚未复跑，不能宣称全部关闭。
- B25/B26：确定失败与结果未知区分、请求重放、取消收尾由故障注入/隔离回归验证；本次真实五轮只证明正常提交路径，不能代替生产并发和远端断连测试。
