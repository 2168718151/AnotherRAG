## 1. 核心结论

1. **禁止动作有漏拦且进入账本。** B批次第三轮候选建议 `notify the requesting user`，在“不得通知任何人”的限制下仍被门控接受并提交。确定性失败回归已复现。
2. **真实知识链无法完成方案零五轮。** 两批均在第四轮出现 `QUERY_TOO_LONG`，第五轮保持阻塞；固定Mock证据下五轮完成不能替代这一结果。
3. **原始ZeRO/GQA五轮未进入数值链。** 两批首轮来源片段超512字符导致 `INVALID_PLAN`；其后梯度修订、对象隔离、预算限定和GQA待补恢复均没有真实闭环证据。这不是金额上限或输出Token用尽。
4. **历史和状态仍有语义错误。** 泛化的 `MISSING_INPUT` 不能告诉用户缺什么；已经补全的歧义仍残留；独立新题带入旧目标；无依据正文“无”被标为 `answered`。
5. **输出余量达标不等于需求容量达标。** 每题最多4096 UTF-8字节却接受至少1500汉字要求，四题均未达字数仍标为已答。
6. **数值检查有误拒及漏检。** 正确的 `1.5 * 2 = 3.0` 被拒，错误的 `2.5 + 2.5 = 6.0` 未被检出。原 `14.68→14.67 GiB` 单表达式回归通过，不能推广为通用算术正确。

这些结果足以阻断验收；平均评估分、请求的 `succeeded` 状态及自动化通过数量不能抵消。
