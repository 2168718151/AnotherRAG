# 子方案 1：会话存储、身份与请求账本

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

依据：[总览](README.md)、[原重建设计方案第 6、10、11 节](../多轮询问模块重建设计方案_20261021.md)。

## 目标

建立 PostgreSQL 长期会话账本和稳定身份边界，让一段多轮交互可持续恢复、按请求幂等提交，并绑定创建时选定的知识库。V1.2 的 Qdrant、Docstore 和现有知识数据不参与迁移。

## 范围

- 会话 UUID、显示名、知识库 UUID、存储指纹、当前 revision、归档状态。
- 轮次请求 ID、请求摘要、expected revision、执行状态、结果引用及必要用量元数据。
- 稳定子题 ID、题号、版本和关系的最小持久化契约；细化规划语义由子方案 2 负责。
- PostgreSQL schema 迁移、连接配置、创建/选择/列出/归档会话的最小接口契约。
- 测试数据库/schema 隔离与迁移回滚验证。

长期账本默认不存整段聊天全文和生成答案正文。完整输入、输出和 prompt 可作为受限测试诊断产物保留，不能混成业务账本。相同 request ID 与相同摘要应返回已知状态；相同 ID 换内容必须作为幂等键冲突处理。

## 不在本阶段

不接入 LLM 规划、历史语义召回、知识检索、答案生成、完整 CLI 交互和生产环境迁移。请求最终提交与 outbox 补偿的端到端行为在子方案 6 验收。

## 唯一快速测试

只使用[唯一连续回归用例](00-唯一连续回归用例.md)的五轮原文。以固定的解析结果 Mock 驱动存储端口，不调用真实模型；同一个会话依次写入五轮。

阶段断言：

- 五轮均绑定同一 session UUID、database UUID 和 storage fingerprint，revision 按成功提交单调变化。
- 每轮有独立 request ID；相同 ID/内容重放不重复创建轮次，相同 ID/不同内容被拒绝。
- 每轮提交的任务、修订关系和状态可按 session 范围读取；拒绝把工单环境自动变成新的会话或知识库。
- 重新打开会话可恢复当前 revision、任务引用和状态；长期业务行中没有完整答案正文。
- 测试只操作隔离 schema；测试结束后核对主库/主集合未改变。

## 完成标准

迁移可在全新隔离 schema 正向执行；模型与存储端口可替换；幂等、revision 冲突、会话绑定和不保存正文的契约均通过。不得通过仅看“表已建好”认定完成。

## 本阶段实施记录

- 本分支新增 `PostgresSessionStore`、版本 1 迁移、生产/诊断 Python 端口和显式迁移脚本；具体契约见[会话账本接口](../conversation_ledger.md)。现有 `query`、Qdrant 和 Docstore 未改动。
- 从方案 0 原文读取五轮，以冻结版本输入提交同一会话；验证 revision 0→5、稳定题号版本、同 ID 重放及冲突、跨范围引用、并发旧 revision、重新打开、归档和不保存答案正文。
- 独立临时 PostgreSQL 实例上的迁移正向、重复执行及故障回滚通过；测试后停止该实例，未操作已有主集群或主集合。Mock 结果不代表模型理解/回答质量已验收。
