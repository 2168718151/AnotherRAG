# 子方案 6：工作流集成、接口与失败恢复

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

依据：[总览](README.md)、[原重建设计方案第 10 至 14 节](多轮询问模块重建设计方案_20261021.md)。

## 目标

将会话账本、任务规划、历史定位、检索、生成和门控组成新的多轮工作流，提供独立 `ask` 及 API 入口，并保证成功提交、确定失败、结果未知和重放行为可区分。现有单轮 `query` 继续保持零生成调用。

## 范围

- 按原方案扩展生产端口和受限诊断端口；同一个会话固定绑定一个知识库身份。
- CLI 创建、选择、列出和归档对话；每轮响应暴露 request ID、revision、逐题状态和最终回答。
- 生产链路按“校验—解析—历史定位—补全—检索—生成—门控—短事务提交—返回”执行。
- 确定失败丢弃未提交候选状态并释放请求；unknown 保留诊断、不自动重复付费请求；成功请求按幂等键重放。
- 提交轮次与索引 outbox 的失败恢复可重试且幂等；不把历史检索索引当权威账本。
- 测试诊断导出阶段 trace、最终 messages、证据映射、参数、usage、错误分类与耗时；凭据不可进入日志。
- 应用与 LlamaIndex 日志写入 `logs/`。

## 不在本阶段

不承诺跨实例共享写存储、不自动升级实验分支遗留 PostgreSQL 表、不改变 Qdrant/Docstore 数据，也不重新运行整套旧的 128 题检索基准。数据库迁移须在隔离 schema 验证，并按原方案检查现存实验数据兼容性。

## 唯一快速测试

使用[唯一连续回归用例](00-唯一连续回归用例.md)作为唯一端到端用户输入。先用各子方案冻结结果及 Mock 组件跑五轮，再按获批范围执行同一输入的真实模型验收；不新建第二条对话样例。

集成断言：

- 第 1 至 5 轮在同一会话 revision 序列中提交，独立工单环境作为独立任务维持清楚边界。
- 所有阶段导出的 task ID、history refs、证据 ID、生成项 ID 和最终输出互相一致。
- 在任一确定失败点注入失败后，本轮未提交任务/条件不会污染上一个已提交 revision；unknown 不会被伪装成 no_evidence 或自动重发。
- 重复 request ID 不重复生成或提交；并发 revision 冲突显式返回。
- 诊断输出能解释第一轮为什么不能定因，以及第五轮如何根据调用记录定位权限策略拒绝；不得包含 API Key。
- `query` 原有预览行为、命名数据库选库及知识库内容保持不变。

## 完成标准

隔离数据库上的全 Workflow 回归通过，所有五轮结果符合唯一用例预期；失败恢复、幂等、revision、诊断、日志与旧 query 回归均通过。真实模型验收报告单独注明模型、接口参数、请求和 token 用量、评分及异常，不能把 Mock 验收描述成生成质量验收。

## 已落地接口与恢复边界（2026-10-25）

- `ConversationWorkflow` 连接规划、历史定位、证据映射、生成、门控及短事务提交；`ConversationTurnResult` 返回 `status/request/revision/answer/items/error_code/answer_not_retained/trace`。同一请求 ID 的成功重放不重复调用模型；由于答案正文不入 PostgreSQL，重启后重放只返回状态、题号及 `answer_not_retained=true`。
- 生产 HTTP 为 `/v1/conversations` 的创建/列表、`/{session_id}/turns` 提问、题目与版本读取、归档、历史索引恢复、unknown 请求显式确认。诊断端口 `/debug/conversations/{session_id}/preview` 只接受已构造的计划与任务输入，导出预算和最终生成消息，不调用模型或提交。请求模型见 `docs/interfaces.md`。
- CLI `shell` 中先 `db use`，再 `conversation create/use` 和 `ask`；`query` 继续为零生成预览。明确题号用 `ask --question Q001`，关闭历史用 `--no-history`，两者不能同时使用。`question list/show/history`、`conversation index recover` 和 `conversation recover --acknowledge-unknown` 支持诊断与人工恢复。
- 确定的提交前失败记录失败并释放会话，不提交候选任务/条件；远端结果或提交确认未知保留 `unknown` 并阻止自动重放。成功提交与历史索引 outbox 标记在短事务内；索引落后通过幂等恢复补齐，不重新生成。调用取消时等待包装任务收尾；不承诺供应商计算或费用可被撤销。
- PostgreSQL 迁移为显式版本 1→2→3；新增历史索引 outbox 不复制 Qdrant 证据正文。仍限单机本地服务与现有物理锁边界，不能据此宣称公网鉴权或多实例安全写入。
- 方案 0 五轮已由真实 API 规划、生成、逐题门控穿过生产会话 Workflow 并连续提交 revision 1→5；跨题范围限制不另生成伪子题，待补工单在第五轮由用户调用记录恢复。此轮证据为固定 Mock，不能代表真实 Qdrant 命中或线上多实例能力。详见[验收记录](方案五六验收记录_20261025.md)。
