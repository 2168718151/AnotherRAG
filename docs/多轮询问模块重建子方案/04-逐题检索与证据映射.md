# 子方案 4：逐题检索与证据映射

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

状态：独立 Python 端口已实现；使用方案 0 冻结上游结果进行隔离 Mock 和 Qdrant 测试，未接入生产会话 Workflow。接口与限制见[逐题检索与证据映射接口](../evidence_mapping.md)。

依据：[总览](README.md)、[原重建设计方案第 7、13 节](../多轮询问模块重建设计方案_20261021.md)。

## 目标

复用当前 Qdrant、JSON Docstore、BM25、RRF 与本地 CUDA Reranker，为每个可回答任务独立检索，并建立严格的“任务可用哪些证据”映射。历史助手答案用于理解上下文，不自动成为知识证据。

## 范围

- 按已解析任务形成精简 search query，保留目标、对象、版本和限制。
- 使用绑定知识库执行向量与 BM25 检索、RRF 融合和 Reranker 重排。
- 对本轮候选节点正文去重，同时保留每个任务自己的 allowed evidence IDs。
- 区分证据不足、缺少用户输入、历史引用失效和检索技术故障。
- 记录 query、节点身份、文档版本、排序分数、耗时及证据充分性诊断。
- 把用户在第 5 轮直接提供的调用记录作为该轮的已给事实输入；不能声称它来自此前的知识库检索。

## 不在本阶段

不改写 Qdrant schema、不重建正式知识库、不自动扩大 Top-K、不把召回分数解释成准确率，也不生成最终答案。真实正反例阈值校准属于整体验收，不在快速 Mock 检查里伪造。

## 唯一快速测试

使用[唯一连续回归用例](00-唯一连续回归用例.md)，以固定隔离知识节点和检索器 Mock 验证每题检索及证据映射；不构造其他用户问题。

阶段断言：

- 第 1 轮调用记录未给出时，工单诊断任务没有可支持具体失败原因的历史或知识证据；输出只能保持未确定并指出所需材料。
- 权限原则与草稿流程任务只能引用其允许的权威节点；禁止的操作不会因节点中出现相关教程而获得执行许可。
- 第 2 至 4 轮复用的历史摘要不进入知识证据池，更新的条件使不再适用的证据标记为需刷新。
- 第 5 轮用户明确提供的日志事实与检索节点分开标记；`missing_write_scope` 及执行器未调用、未创建记录均能追溯到该轮输入。
- 单一任务不能引用仅授权给其他任务的节点；同一节点服务多题时只去重正文、不去重关联。

## 完成标准

输出可重复的任务到证据映射与版本；不存在跨库候选、无依据归因、把历史答案当事实或跨题引用扩权。原检索预览 `query` 的零 LLM 调用行为保持不变。
