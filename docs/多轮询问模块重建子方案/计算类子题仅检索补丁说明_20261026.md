# 计算类子题仅检索补丁说明

> 历史资料说明（2026-11-06）：以下设计、实施过程、基线与验收结果按文中原日期保留，不作为当前功能状态或可直接执行的部署步骤。当前说明见[文档导航](../README.md)。本次未重新运行原验收，也未把历史失败改成通过。

日期：2026-10-26。适用于当前多轮会话功能分支。用户已确认：暂不执行计算；计算类子题查询当前绑定知识库，有适用的已有问答答案则返回，没有则输出“无”。

## 工作流与实现

```text
整条消息规划并逐题标记 answer_mode
→ 保留会话、知识库、revision 与历史目标校验
→ 继承或修订有效查询条件，不为了演算补参数
→ 逐题使用现有混合检索与可信 Docstore 核验
→ 计算题：提取完整已有 Q&A → 数值/单位初筛 → 模型只选择候选 ID
          → 程序读取被选答案原文，或返回“无”
→ 普通题：保留原生成与逐题门控
→ 按输入顺序合并，提交题目状态与证据引用
```

- 计算题不进入生成、答案重写或算术修复；不代入公式、做单位换算或计算比例。
- 同一消息的概念解释和数值计算应分别规划。单题的 `calculation_lookup` 不扩散到其他独立题目。
- `PlannedTask.answer_mode` 为 `standard`、`calculation_lookup` 或 `null`。旧冻结计划可省略；条件型追问使用 `null`，程序从实际定位的历史题目继承。明确转为概念问题可使用 `standard`。另有中文/英文直接计算措辞的保守识别兜底，无法保证识别所有自然语言表达。
- 有效模式写入该题 `effective_state` JSONB；不新增表、不迁移主库、不创建或重建向量索引。
- 原有计算参数缺口不再阻塞查库；必要的指代/对象澄清仍保留。改变 batch 等参数后必须重新检索，不能把旧答案当本题答案。

## 已有答案的边界

1. 复用现有 `Q:/A:`、`问题：/答案：` 等 TXT 解析规则。只有完整问答及答案正文才可选；纯公式或历史助手回复不是现成本题答案。
2. 同义措辞可以由匹配模型判断；对象、参数与字段对应关系、假设和单位口径必须适用。程序先核对字面数字与单位，拒绝显然不符的候选；交换参数字段、不同对象等语义适用性由匹配模型检查，不能将这一步宣称为程序证明。
3. 程序不进行数值换算来证明适用，例如 `1024 MiB` 不能自动套用 `1 GiB` 的问答。`byte/bytes/字节` 作为同一单位的语言别名允许匹配。
4. 生产映射器从同一可信 Document 提取当前检索节点对应的完整 Q&A，避免把分块后的半段答案当完整答案。节点/文档身份、版本与提交前失效检查继续适用。
5. 匹配 API 只返回 ID、题目身份和适用性标记；Schema 禁止返回新答案字段。原文答案由本地程序提取，不采用模型自行生成的计算结果。
6. 检索无候选、只有公式、参数不适用或匹配模型确认无完整现成答案：`no_evidence`，答案为“无”。检索故障、非法匹配输出、越权候选或超限仍是技术失败。
7. 本策略仍受现有 Top-K 召回范围影响；“无”表示本次检索未取得适用答案，不证明整个库内绝对不存在。库中原答案的算术正确性也不在本补丁的演算验证范围内。
8. 超过现有单题答案字节容量的原文不截断、不压缩成新答案，返回 `STORED_ANSWER_TOO_LONG`。格式要求不能触发计算结果的新计算或改写。

## 生产与诊断接口

HTTP/CLI 沿用会话 `turns` 与 `ask`，无需新增客户端请求参数。`items` 继续保留每道题目 ID、版本、状态、答案与证据引用。

Python 端口：`TaskPlanningPipeline.plan()` → `ConversationWorkflow.answer_turn()` → `ConversationAnswerPipeline.answer()`；单体诊断可注入规划、证据和 Mock 模型。

`ConversationTaskInput.answer_mode` 支持明确注入，省略时按当前题目直接措辞判断。`EvidencePoolEntry.complete_qa_pairs` 为当前请求的完整问答候选，不写回知识索引或会话正文；省略时仅供旧测试/诊断兼容，从输入节点文本解析。

`preview(..., include_messages=True)` 返回 `calculation_lookups`：题目 key、候选 ID、输入预算、输出预留、是否需要匹配调用和匹配 messages。普通生成 messages 与匹配 messages 分开；零模型预览不执行匹配。

匹配阶段为 `qa_match`，复用原调用器的日志、usage、响应上限、finish reason、未知调用保护与诊断归档。每题至多一次匹配调用，输出使用现有 gate 预算；非法输出不进入生成修复。生产诊断 `trace.calculation_lookups` 导出对应输入，`trace.generation.metrics` 记录耗时和 Token。日志继续写入 `logs/`。

## 针对性回归

文件：`tests/test_calculation_lookup.py`。隔离 PostgreSQL 使用独立临时实例，知识与检索夹具不操作主数据库。

| 场景 | 样例/变体 | 核验内容 |
| --- | --- | --- |
| 已有答案命中 | 同配置 KV cache 问答 | 逐字返回答案、附可信引用，只有匹配调用 |
| 中英改写 | Calculate 改为 How much memory | 匹配成功后仍读取原文，不让模型重写 |
| 没有完整问答 | 空候选、历史回复、答案为“无” | 不生成、不算术修复，输出 no_evidence/无 |
| 仅有公式 | 相同问题但答案只有变量公式 | 不能代入用户事实演算 |
| 参数与单位不同 | batch 2/3、FP32/FP16、GiB/MiB | 字面不符即排除，不能换算 |
| 交换参数或不同对象 | batch/seq 对调、KV cache/优化器 | 模型语义匹配须拒绝；Mock 只验证拒绝结果的程序处理 |
| 非法匹配响应 | JSON 错误、跨题 ID、虚构答案字段 | 技术失败，有限调用，不返回伪造答案 |
| 多题混合 | 无答案计算题＋普通题＋检索故障题 | 各题状态独立，数量与顺序保持 |
| 多轮修改 | batch 2 命中→11 无答案→加入11问答再查 | 保留题目身份、更新条件、重新检索，不要求补 layers |
| 完整性/预算 | 分块片段、过长答案、输入容量不足 | 使用完整 Q&A，禁止静默截断，调用前预检 |
| 非计算边界 | 计算图原理、概念追问、指代歧义 | 不污染概念问题，歧义仍澄清 |
